The Problem

The Friction in Traditional E-Commerce

  • Rigid Navigation: Users must manually filter, search, and click through multiple pages.
  • Lack of Personalization: Static search bars cannot answer contextual questions like "What ingredients do I need for a salad for 3 people?"
  • High Cart Abandonment: The longer it takes to find and add items, the higher the drop-off rate.
Talking point: "I wanted to build a platform where shopping feels as natural as texting a store clerk."

The Solution

AI-Driven Conversational Shopping

  • Conversational Interface: A persistent, slide-out chat drawer accessible from anywhere.
  • Agentic Capability: The AI actively manages the cart, checks inventory, and places orders on behalf of the user.
  • Context-Aware: Remembers session history and user preferences natively.

Bridging Natural Language and Databases

  • Dynamic Tool Calling: The assistant uses backend Java `@Tool` methods to read the database and mutate state autonomously.
  • Semantic Understanding: The AI can reason about complex quantities (e.g., automatically adding 3 of each item when asked to prepare for 3 people).
  • Real-time Sync: Backend cart modifications instantly trigger UI re-renders without full page refreshes.

Security & Guardrails

Taming the LLM in the Backend

  • Enforced Confirmations: Irreversible actions (`placeOrder`) are protected by a backend Java interceptor that forces the AI to stop, present a summary, and wait for a human "Yes".
  • Boundary Control: Strict System Prompts prevent the AI from answering off-topic questions (e.g., programming or general knowledge) to avoid prompt injection.
  • Data Privacy: Internal database IDs are strictly hidden from the user.

Technical Architecture

  • Backend: Java Servlets deployed on Apache Tomcat (built from the ground up for deep understanding of HTTP and state).
  • AI Orchestration: LangChain4j bridging the Java backend with the Google Gemini API.
  • Database: PostgreSQL with schema versioning via Flyway.
  • Frontend: Vanilla JavaScript and HTML5 with dynamic DOM manipulation (zero-dependency approach for maximum performance).

Overcoming Hurdles

  • API Rate Limits: Navigated strict LLM rate limits by optimizing token usage and switching models.
  • Sequence Errors: Solved complex `ChatMemory` eviction bugs that broke Gemini's strict User -> Model -> Tool turn sequence.
  • The "Agentic Loop": Forced the model to pause its execution loop to ask for human permission by shifting validation logic from the LLM prompt to hard-coded Java constraints.

Future Roadmap

  • Integration of a real payment gateway (Stripe) via chat links.
  • Voice-to-text integration for hands-free shopping.
  • RAG (Retrieval-Augmented Generation) for querying thousands of product reviews.
